# Claude·GPT 제작 인계 및 검증 기준

SERIES-R1 · 2026-10-23

## 1. 이 문서의 사용법

제작자는 기존 1화에서 Claude가 UI/UX·구현을 맡고, Codex/GPT와 이미지·대사 작업 및 플레이 리뷰를 협업하는 방식으로 개발했다. 2~4화도 이 방식을 이어간다. 아래 역할은 제작 권고이며 특정 모델이 어떤 작업에서 우월하다는 성능 비교는 아니다.

이 패키지는 서사 설계다. 바로 수천 줄의 대사를 생성하거나 엔진을 한꺼번에 바꾸지 말고 한 화의 논리·회색 화면 프로토타입·실제 플레이를 차례로 검증한다.

## 2. 문서와 구현의 분리

| 구분 | 기준 | 변경 권한 / 처리 |
|---|---|---|
| 시리즈 핵심 | `story-bible.md`의 로그라인·독립 사건·승리의 성과 편입·인물 성장 | 바꾸려면 제작자에게 영향 설명 후 합의 |
| 권장 사건 설계 | `episodes.md`의 인물·범행·공방·복선 | 작성자 제안. 논리 검증에서 필요하면 수정안을 제시 |
| 미검증 장치 | EP2 난간 구조, EP3 손상·도착 시각 연결, EP4 현장 입증 | 대본 확정 전 검증. 실패하면 장치 재설계 |
| 구현자 재량 | 단역 이름·가벼운 농담·세부 UI 배치·보조 대사·장면 분할 | 핵심 사실·복선 시점·관계와 충돌하지 않으면 자율 결정 |
| 현행 EP1 | `ep1-rewrite.md`, `records.ts` | 연결 장면 이외 변경은 별도 이유와 회귀 검증 필요 |

장면 대사의 예시는 의도 전달용이다. 모든 예시를 실제 대사로 채택하지 않는다. 과도한 명언·주제 반복을 줄이고 인물의 당면 목표에 맞게 구어체로 다시 쓴다.

## 4. 화별 제작 순서와 산출물

### 단계 A — 사건 논리 설계

각 화 디렉터리의 `case-truth.md`에 다음을 먼저 쓴다.

1. 실제 범행을 거짓말 없이 서술한 1페이지.
2. 분/초 단위 기준 시간표. 시간 오차와 공통 사건으로 동기화하는 방법 포함.
3. 지도. 출입 가능 경로, 목격 사각, 물건의 위치와 이동.
4. 모든 인물의 시간대별 위치·아는 것·모르는 것·거짓말 이유.
5. 증거마다 출처, 생성 시점, 확보·보관 경위, 입증 범위, 한계, 반박.
6. 피고인 무죄 논증과 진범 행위 논증을 분리한 표.
7. 자백과 우연한 말실수를 모두 제거해도 남는 최종 논증.

이 단계에서 다른 모델/검토자에게 ‘가장 설득력 있는 대안 설명을 만들어 달라’고 요청한다. 반론이 나오면 대사로 우겨서 막지 말고 사건 자료를 고친다.

### 단계 B — 플레이 흐름

`play-flow.md`에는 장면마다 다음을 쓴다.

| 항목 | 요구 |
|---|---|
| 시작 시 알고 있는 사실 | 플레이어가 실제로 앞서 접한 것만 |
| 지금의 질문 | 한 문장. 범인·정답을 암시하는 제목 금지 |
| 플레이어 행동 | 관찰·제시·흔들기·비교·질문 재구성 중 하나 |
| 받아줄 정답 | 논리가 같은 여러 증거·표현 허용 |
| 이른 정답 | 사실은 인정하고 남은 부분 설명, 벌점 없음 |
| 합리적 오답 | 어느 전제 하나가 틀렸는지 구체적으로 |
| 힌트 | 쟁점 → 자료 범위 → 구체적 연결 |
| 성공 후 달라지는 것 | 사실·혐의·관계·새 질문 |
| 다음 장면 연결 | 누가 왜 다음 자료/사람을 찾는가 |

퍼즐의 제목·선택지가 정답을 먼저 말하지 않는지 검토한다. NPC가 정답 증거를 이름으로 가리키기 전에 플레이어가 판단할 틈을 준다. 필수 증거를 못 찾아 무한 조사하게 하지 말고 조사 목적과 남은 항목을 명확히 한다.

### 단계 C — 회색 화면 구현

기존 엔진·임시 도형·텍스트로 한 공방씩 만든다. 새로운 UI는 각각 최소 하나의 실제 퍼즐에서 사용해 본다. 완성 이미지를 먼저 만들지 않는다.

권장 공통 도구: 원본/가공본 비교, 사실/주장 보드, 요청형 힌트, near-miss 메모, 저장 체크포인트.

| 화 | 새 인터랙션 권장 | 기존 기능 재사용 |
|---|---|---|
| EP2 | 두 도면/사진의 고정부·상태 비교. 문서 표의 다른 항목 지목 | 사진 비교, 평면도, 조사 |
| EP3 | 원본·생성·전송 기록 세 카드 연결. 음성 구간 자막 비교 | 녹음 재생, match, 기록 덧붙임 |
| EP4 | 증언의 관측 출처를 묻는 질문 재구성. 법원/회사/발주처 자료 비교 | ask, match, 조사, 사진 |

새 기능이 스토리를 위한 것인지, 기능을 보여주려고 불필요한 퍼즐을 넣은 것인지 구별한다. 음성을 실제로 듣지 않아도 자막과 명확한 자료로 풀 수 있어야 한다.

### 단계 D — 대사·아트

인물 말투·장면 의도·허용된 사실·금지할 과잉 결론을 주고 대사를 작성한다. 대사 작성자에게 시리즈 전체 진상만 던져놓고 각 증인이 무엇을 아는지 추측하게 하지 않는다.

증거 이미지는 도면 확정 후 생성한다. 위치·시간·균열·부품 등 논증에 필요한 사실은 좌표/벡터/텍스트 오버레이로 통제한다. 이미지 생성 모델이 임의로 그린 흠집을 증거로 채택하지 않는다. 기존 `art-guide.md`의 스타일과 인물 참조를 사용한다.

최종 그림 제작 순서: 현장 도면 → 임시 그림으로 논리 검증 → 배경·인물 → 증거용 고정 구도 → 필요한 상태 차이. 비교 그림은 같은 기반을 사용한다.

### 단계 E — 세 종류 리뷰

**논리 리뷰:** 스포일러 전체를 읽고 대안 가설, 증거의 과잉 해석, 확보 경위를 공격한다.

**초회 플레이 리뷰:** 사건 설계서·정답·시리즈 비밀을 읽지 않은 검토자가 처음부터 플레이한다. ‘다음에 뭘 해야 하는지 모르겠다’, ‘여기서 이미 답을 알았다’, ‘이 사람 마음이 이해 안 된다’를 시간·장면과 함께 기록한다.

**개선 확인 리뷰:** 수정한 구간과 영향받은 저장·분기만 재확인한다. 새로운 우려가 없는데 전체 게임을 반복 플레이하게 하지 않는다.

한 검토자가 설계서를 읽고 플레이한 결과를 ‘초회 이해도’라고 보고하지 않는다. 플레이 리뷰는 실제 실행과 행동에 근거하며 코드만 읽은 평가는 별도로 표시한다.

## 5. 리뷰 기록 양식

```md
# EPn 리뷰 — 버전 / 날짜

검토 방식: 논리 문서 / 스포일러 없는 실제 플레이 / 수정 확인
플레이 시작점과 종료점:
실제로 실행한 것:
읽은 설계 자료(있으면):

| ID | 장면/증언 | 관찰한 문제 | 플레이어 영향 | 근거 | 권장 수정 | 재확인 결과 |
|---|---|---|---|---|---|---|

우선순위:
- P0: 사건이 논리적으로 성립하지 않음 / 진행 불가
- P1: 정답 도출에 필요한 정보 미제공 / 인물의 핵심 행동 모순
- P2: 설명 과다·감정 급전환·불공정한 오답 처리
- P3: 말투·연출·선택적 개선

해결하지 않은 반론:
제작자가 결정해야 하는 변경:
```

리뷰 요청은 한 번에 목적 하나를 명확히 한다. ‘재미있게 전체 개선’보다 ‘이 공방에서 피고인 부재를 증명하는 데 빠진 자료가 있는가’처럼 구체화한다. 발견한 문제를 고치는 동안 앞서 합의한 범행 진상을 몰래 바꾸지 않는다.

## 6. 대본 구현 전 반드시 닫을 설계 과제

아래는 제작자에게 취향을 다시 물어야 하는 질문이 아니라, 제작팀이 조사·도면·검토로 해결할 항목이다. 현재 문서가 이 부분까지 검증 완료되었다고 주장하지 않는다.

| ID | 과제 | 완료 조건 |
|---|---|---|
| G2-1 | EP2 난간 장치의 기계적 가능성 | 구체 도면과 하중/움직임 설명. 사전 해체가 실제 추락으로 이어짐 |
| G2-2 | EP2 수리와 살해 유도의 구분 | 제거자·위험한 결속·유도 메시지의 행위자·의도가 증거로 연결 |
| G2-3 | EP2 소윤의 행위 | 붙잡기와 밀기의 관측 한계를 명확히 하고 무죄 판단을 과잉 확정하지 않음 |
| G3-1 | EP3 학생 도착 전 치명상과 추가 가해 반론 | 사망 시각 추정에 기대지 않는 독립 증거 구성 확정 |
| G3-2 | EP3 합성·전송·조작자의 연결 | 공유 계정·예약 전송·도용 반론 검토, 서비스 보관 범위 확정 |
| G4-1 | EP4 치명상 발생 구간 | 외부 상담 알리바이와 겹치는 구간을 하은 기억만으로 정하지 않음 |
| G4-2 | EP4 공격·낙상·구조의 구분 | 전문가 검토 가능한 물증·공간 논증. 피 묻은 옷만으로 결론 금지 |
| G4-3 | EP4 실제 출입자와 사각 | 계정/카드=사람이 아닌 신원·출입 인원 확인 |
| G4-4 | EP4 은폐 승인자의 고의 | 정정 수신→승인→반영→외부 제출의 독립된 보관 근거 |
| UX-1 | 산출 중단과 재검토 기회의 분리 | 판관이 중단되어도 조작·실패 피드백 정상, 고장처럼 보이지 않음 |

핵심 반전·인물 관계를 바꾸지 않고 위 과제를 해결할 수 있다. 물리 장치 변경이 다른 화의 복선을 바꾸면 F번호로 영향 범위를 기록한다.

## 8. 이 패키지에서 하지 않은 것

- 게임 코드와 저장 데이터 수정, 2~4화 공개, 배포.
- 물리 장치의 실험·법의학 검증, 최종 초 단위 스펙 확정.
- 새 아트·음악 제작, 실제 플레이 테스트.
- 특정 모델이나 도구의 성능 비교.

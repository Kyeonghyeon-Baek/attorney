# 그림·화면·조작 개선 사양

2026-10-24 · EP1-Q1

## 1. 확인 범위와 방향

현재 대본·엔진·CSS를 읽었고 `sceneItems.png`, `alley.png`, `storeroom.png` 원본을 직접 확인했다. 아래 그림 불일치는 실제 파일에서 관찰했다. 반면 화면 가독성 수치는 **개정 목표**이며 실제 휴대폰 플레이로 확인한 결함 수치가 아니다. 구현 후 브라우저에서 검증한다.

기존 캐릭터, 남색·코랄색, 법정 배경, 픽셀 대사체와 기록용 고딕을 유지한다. 증거의 정확성과 읽는 순서를 먼저 고친다. 장식용 CG 대량 추가는 하지 않는다.

## 2. 필수 이미지 수정

### ART-01: `src/assets/items/sceneItems.png` — 상패 증거 정합성

현재 그림: 금속 받침에 아크릴의 부러진 밑동이 남고 작은 조각들이 한 봉투 안에 있다.

현재 사건: 판 전체가 받침에서 빠져 바닥으로 이동했고, **판의 왼쪽 아래 모서리**가 깨졌다. 판 본체는 오정택의 가방, 받침은 현장, 상처 조각은 부검에서 각각 확보했다. 지금 그림은 파손 위치와 수거 경위를 모두 잘못 떠올리게 한다.

**수정 사양**:

- 1024×1024 투명 PNG. 증거 카드용 일러스트. 기존 금속 받침 중심 그림을 **가방에서 확보한 아크릴 판 본체 중심**으로 교체.
- 판은 대부분 온전한 직사각형이고, 정면 기준 왼쪽 아래 외곽만 결손. 형태 기준은 `engine/photos.ts`의 `PLATE_NOTCHED`와 `SHARDS`.
- 본체가 개별 봉인 봉투에 들어 있다. 금속 받침이나 상처 속 세 조각을 같은 봉투에 넣지 않는다. 수거 위치 목록은 기존 기록의 표로 설명한다.
- 텍스트·시각·증거번호는 그림에 생성하지 않고 UI에서 표시.
- 이 작은 아이콘 자체로 파단면 맞춤을 판별시키지 않는다. 정확한 윤곽은 SVG 분석 도식에서 표시한다. 일러스트와 SVG의 결손 위치는 같아야 한다.
- 반전 공개 전에는 ‘상처와 일치하는 세 조각’ 표시를 넣지 않는다. 깨진 판을 이미 압수했다는 정보만 보여 준다.

생성/편집 브리프:

> 기존 판 뒤집기 증거 그림의 선과 색감을 유지한다. 투명 배경 위에 투명 경찰 증거 봉투 한 개. 봉투 안에는 받침에서 통째로 빠진 두꺼운 직사각형 아크릴 상패 판 본체가 있다. 판은 대부분 온전하고 정면 기준 왼쪽 아래 모서리만 불규칙하게 깨져 없다. 나머지 세 모서리는 온전하다. 받침, 받침에 남은 밑동, 별도 작은 파편은 그리지 않는다. 읽을 수 있는 글자·숫자·로고 없음. 정확한 결손 윤곽은 참조 SVG와 일치시킨다. 1024×1024, 실제 알파 투명 PNG.

`docs/art-guide.md`의 기존 `sceneItems` 프롬프트도 반드시 교체한다. 그렇지 않으면 다음 생성에서 같은 오류가 돌아온다.

### ART-02: `src/assets/cg/alley.png` — 골목의 거리·문·봉지

현재 그림: 태오와 할머니 바로 옆에 활짝 열린 뒷문이 있으며 음식이 투명 봉지에 보인다. 사건에서 태오는 검은 폐기 봉지를 들고 나와 문을 닫고 약 50m 떨어진 할머니에게 간다. 현재 CG는 녹음기가 여전히 열린 창고 문 바로 앞에 있다는 오해를 만든다. 이 그림은 `grandma`와 사건 목록 썸네일에서 사용한다.

**수정 사양**:

- 1536×1024 불투명. 기존 두 인물의 외형·옷·손수레·따뜻한 가로등 분위기 유지.
- 전경: 태오와 할머니. 검은 불투명 봉지의 입구가 열려 있고 포장 음식이 위쪽으로 조금 보임. 음식 개수를 새 사실처럼 강조하지 않음.
- 가게 뒷문은 먼 배경의 작고 **닫힌** 문으로 표현하거나 프레임 밖으로 뺀다. 문이 인물 바로 뒤에 있지 않게 한다.
- 거리의 정확한 미터값은 그림의 원근만으로 증명하지 않는다. 기존 대사·기록으로 설명한다.
- 창고 내부, 피해자, 오정택은 보이지 않는다.

편집 브리프:

> 첨부된 기존 골목 CG의 인물, 손수레, 따뜻한 밤 분위기를 보존한다. 두 사람은 가게에서 떨어진 골목 가로등 아래에 있다. 바로 뒤의 열린 문과 보이는 실내를 제거하고 그 자리는 연속된 골목 벽으로 바꾼다. 가게 뒷문은 먼 배경에 닫힌 작은 철문으로만 보이거나 화면 밖이다. 투명 봉지를 검은 불투명 비닐봉지로 바꾸고, 열린 입구에 포장된 음식 일부만 보이게 한다. 글자나 시간표시는 생성하지 않는다. 1536×1024.

`docs/art-guide.md`에서 ‘열린 뒷문 틈’과 투명 봉지를 유도하는 문구를 함께 수정한다.

### ART-03: `src/assets/bg/storeroom.png` — 카메라 시야와 공간 정합성

현재 일반 창고 배경에는 천장 카메라와 뒤쪽 철문이 같은 열린 통로에 보인다. 이것만으로 광학적 시야가 확정되지는 않지만, 지도와 CAM3 설명의 ‘뒤쪽 문은 꺾인 통로 너머’와 다르게 이해될 수 있다.

**이번 사양의 기본 수정은 일반 창고 배경의 천장 카메라를 제거하는 것**이다. 이 배경을 CAM3 촬영 화면처럼 취급하지 않는다. CAM3는 별도 `cg/cctv3.png`가 담당한다. 배경 수정 시 창고 전체를 재생성하기보다 카메라 부분 편집을 우선한다.

- `engine/maps.ts`를 공간의 기준으로 삼는다. 화면상 좌우는 카메라 각도에 따라 다를 수 있지만 길의 연결과 시야 차폐는 같아야 한다.
- `cctv3`를 구현 검수 때 직접 열어 뒷문·피해자가 보이지 않는지 확인. 맞으면 그대로 사용한다.
- 일반 배경에서 문이 보이는 것은 허용한다. ‘일반 배경 시점=카메라 시점’이라는 표시를 붙이지 않는다.
- 지도에 없는 창문·출입구·가해자가 넘을 수 있을 만큼 낮은 선반을 새로 그리지 않는다.

## 3. 유지·개선할 증거 시각화

### ART-04: 112 사진과 파편 도식 — 코드로 정확하게

`share112-base.png` 한 장 + `photos.ts`의 공통 SVG 상패/파편 구조를 유지한다. 7장의 사진을 각각 이미지 생성하지 않는다. 도식은 이미지 생성보다 SVG가 적합하다.

- 원본 사진은 `02:55:38, 48, 58, 02:56:08, 18, 28, 38`과 기존 관측 상태를 유지.
- 사진 보기의 시각은 ‘촬영’, 수신 시각은 상세 정보에 구별. 화면 속 글자로 굽지 않음.
- 상처 조각과 본체의 관계를 확대 도식으로 표현하되 **‘감정 설명도 · 촬영 사진 아님’**을 명시.
- 사진의 대응 영역 표시와 도식의 세 조각에 같은 번호/무늬를 사용. 색만으로 구분하지 않는다.
- `photomark:share112` 전에는 상처 대응 번호를 숨긴다. 단순 파손 상태 자체는 처음부터 관찰 가능.
- 사진을 클릭한 즉시 정답 확정하지 않는다. 현재 ‘선택 → 확인’ 동작 유지.
- 파손 구간 결과: “이 부분은 02:55:48에는 있고, 02:55:58에는 없다.” 여기서 머리 손상 시각을 확정하지 않는다.
- 확대 분석에서 판을 회전했다면 ‘비교를 위해 회전’ 표시. 원본 사진과 같은 방향인 척하지 않는다.

### ART-05: 지도

기존 `maps.ts` SVG 재사용. 별도 지도를 AI로 새로 그리지 않는다.

- 기본 지도: 매장/창고/골목 출입, 천장까지 선반, 피해자 발견 지점.
- C01 정답 이후: CAM1·CAM3 관측 범위와 카메라 밖 구역을 범례로 구별. 숫자·아이콘·선 모양을 함께 사용.
- 관측된 동선은 실선, 검찰 가설은 점선 + ‘검찰 주장’. 화면 밖 이동을 CCTV로 촬영한 것처럼 실선으로 연결하지 않는다.
- 정답 이전에는 새 강조나 점멸로 클릭할 위치를 알려 주지 않는다. 기본 지도에 원래 있는 사실은 숨기지 않음.

## 4. 요청형 도움말과 현재 공방 요약

### UX-01: 상시 쟁점 HUD를 복원하지 않는다

현재 `game.ts`의 `issue`는 `issue|…` 상태를 보존하지만 화면에는 렌더링하지 않는다. 기존 문서에 상시 표시 설명이 있어도 현재 구현과 다르다. 이 사양은 HUD를 다시 늘리는 대신 **법원기록 안에 요청형 요약**을 둔다.

법원기록 헤더에 `이번 공방` 버튼 추가. 누르면 기존 기록 패널 안에서 다음을 표시한다:

1. 현재 질문 한 문장.
2. 플레이어가 이미 확인한 사실 최대 3개.
3. 아직 확인할 점 한 문장.

닫으면 보던 기록/선택/스크롤로 돌아간다. 힌트 단계 사용으로 계산하지 않는다. 아직 발견하지 않은 사실·정답 증거명은 표시하지 않는다. 장면 전환/정답 후에만 바뀌며 증언마다 갱신되는 긴 실시간 로그로 만들지 않는다.

구현 계약(기존 `issue`와 별개로 최소 확장):

```ts
type Recap = { question: string; facts: string[]; pending: string };
// Cmd에 새 명령, script.ts에 helper, game.ts 처리. 이름은 recap으로 통일.
// recap(null)은 숨김. facts는 0~3개.
recap({ question: '...', facts: ['...'], pending: '...' });
```

- 저장은 현재 flags 기반 방식에 맞춰 `recap|` + JSON 한 항목을 교체하는 방식. 읽을 때 파싱 실패는 숨김 처리. 저장 형식 전체를 바꾸지 않는다.
- `CaseData`의 다른 화는 이 명령을 쓰지 않으면 버튼이 나오지 않는다.
- 기록 모달 내부 뷰이므로 하위 게임 조작을 통과시키지 않는다. 새 게임/화 전환/재개 시 이전 사건 recap을 지운 뒤 복원.
- 첫 안내는 C01 종료 후 수첩 안내와 합쳐 한 번만. “헷갈리면 법원기록의 ‘이번 공방’에서 확인한 내용을 볼 수 있어요.”

기본 내용표(성공 후 단계가 더 구체적이면 아래 내용을 교체하고 누적하지 않음):

| 갱신 지점 | 질문 | 확인한 사실 | 남은 점 |
|---|---|---|---|
| `trial` 끝 | 창고에 있던 사람은 태오뿐이었을까? | 태오는 창고에 들어갔다 / 검찰은 그때 가해했다고 주장 | 기록이 보여 주지 않는 곳 |
| `cross0` 성공 | 목격자는 무엇을 직접 보았을까? | 창고 구석과 뒷문은 카메라 밖 | 신고자의 관찰 근거 |
| `recess` | 봉지와 당시 상황을 누가 설명할 수 있을까? | 유리창 목격 철회 / 02:45 태오는 매장 | 봉지를 받은 사람의 이야기 |
| Q05 성공 | 먼저 충돌한 사람은 누구일까? | 첫 충돌 때 태오는 매장 / 봉지는 골목으로 이동 | 녹음 속 상대의 신원 |
| Q07 후~`afternoon` | 머리 손상은 언제 생겼을까? | 첫 폭행은 오정택 인정 / 머리 손상은 별개 | 첫 폭행 뒤의 행적 |
| `outside` 완료 | 머리 손상과 상패는 어떻게 연결될까? | 태오의 퇴장 후 행적 확인 / 오정택 퇴장 주장 철회 | 상처 속 조각의 출처 |
| `waiting` | 조각은 어디에서 왔을까? | 판·현장 조각·상처 조각 대조 중 | 감정 결과 |
| `result` 시작 | 감정 결과와 사진을 함께 보면 무엇이 달라질까? | 태오의 이후 행적 확인 / 감정 도착 | 자료를 연결한 의미 |
| 새 Q10 성공 | 처음 신고는 확인된 사실과 맞을까? | 방문 당시 머리 가해 설명 무너짐 / 복귀는 경찰 동행 | 신고 내용의 근거 |
| `verdict` 후 | 숨김 | — | — |

CP는 정상 진행에서 도달한 같은 시점의 recap을 포함한다. `result` CP에서 새 Q10 정답 내용이 먼저 보이면 실패다.

### UX-02: 힌트 접근

현재 수동 힌트·3단계·저장·기회와 분리하는 정책 유지. 새로운 자동 정답 안내는 만들지 않는다.

- 반대신문의 하단 행동 줄에 `힌트` 버튼을 직접 노출(PC/터치 모두). `hintCtx`가 있을 때만 활성.
- `choose`, `match`, `photoTask`에도 해당 화면 안에 같은 버튼을 둔다. 이미 있으면 중복하지 않는다.
- PC H는 유지, 터치는 키 이름 대신 버튼 이름. 힌트 뒤 원래 증언/선택/사진 단계와 선택 상태로 복귀.
- 힌트를 연다고 선택이 확정되거나 재검토 기회/예측이 변하지 않음. 3단계만 사용량 집계.
- 화면 전체 클릭으로 대사 진행하는 핸들러와 충돌하지 않게 모달 입력 스택 사용. 연타로 즉시 3단계가 열리지 않게 기존 입력 가드 재사용.

### UX-03: 현재 기록을 찾기 쉽도록

- 감정서 덧붙임이 생기면 기존 `showRecord` 방식으로 해당 추가 내용부터 펼침. 원문을 덮어쓰지 않음.
- 기록의 ‘확인되는 것/알 수 없는 것’은 유지하되 첫 요약은 평범한 한 문장. 긴 주의 문구를 카드의 시각적 주제로 만들지 않음.
- 추론 후 `memo`에 새 결론을 적되, 원래 자료의 `proves`에 미래의 답을 미리 적지 않음.
- 기존 수첩/대사 기록/이번 공방의 역할: 누적 사실 / 실제 대화 / 현재 단계 요약. 세 곳에 같은 장문을 복사하지 않음.

### UX-04: 읽기·터치 기준

검수 뷰포트: PC 1280×720, 1440×900 / 터치 가로 844×390, 667×375. 세로는 기존 회전 안내 유지. 1280×720 무대 좌표와 실제 CSS 표시 크기를 구별한다.

- 핵심 본문은 실제 표시 크기 16px 이상을 목표로 한다. 기록/힌트/정답 선택지에서 먼저 적용. 공간이 부족하면 스크롤과 별도 확대를 사용하고 글자를 일괄 축소하지 않는다.
- 주요 확인/닫기/힌트 버튼은 실제 표시 기준 약 44×44px 이상 목표. `--scale`로 줄어든 최종 영역을 측정한다.
- 사진 부위는 작은 점을 정확히 누르게 하지 않는다. 기존 후보 영역 선택과 텍스트 라벨을 유지하고 터치 영역을 넓힌다. 후보 영역이 겹치면 확대 단계로 분리한다.
- 작은 휴대폰에서 4×2 카드를 모두 작은 글자로 우겨 넣지 않는다. 한 줄씩 스크롤/페이지 이동 가능하게 하고 고른 카드 요약·확인 버튼은 접근 가능하게 유지.
- 시간표를 색만으로 해석시키지 않는다. ‘관측’, ‘주장’, ‘미확인’ 텍스트와 선 모양 병용.
- 새로운 본문/요약 패널은 굵은 픽셀 글꼴 대신 현재 기록용 고딕 사용. 캐릭터 대사 글꼴은 유지.
- 사진 비교 전체/확대/도식 상태 어디서든 닫기·힌트·확인 버튼이 잘리지 않아야 함. 필요하면 패널 내부 스크롤, 하단 행동 줄 고정.
- 판관 수치·기회·도움말이 증거를 가리지 않게 한다. UI의 새 높이가 HUD에 영향을 주면 `--hud-bottom` 계산도 갱신한다.

## 5. 선택 이미지/연출 — 필수 작업 이후

새 그림 없이 기존 표정과 침묵만으로 충분하면 생략 가능. 작업을 생략해도 필수 완료 기준에는 영향 없다.

- `cg/ep1-meal.png`: 마지막 삼각김밥을 받아 든 단비의 손과 주변 인물 일부. 따뜻한 결말의 한 장면. 피해자를 웃는 유령으로 등장시키지 않음. 생성 시 기존 인물 참조 필수.
- 서지훈 표정: 기존 `normal`·`sweat`를 먼저 확인. 노골적으로 음흉한 미소/악역 조명은 1화에 쓰지 않음. 필요할 때만 차분한 경청 표정 추가.
- 첫 폭행 인정 뒤 BGM을 짧게 쉬고 태오의 안도 표정을 보여 준 후 Q07. 새 음악 제작은 범위 밖. 현재 변경 중인 오디오 시스템과 충돌하지 않게 기존 호출 사용.

## 6. 이미지 납품 체크

- 교체 전 원본을 참조하고 같은 인물·화풍 유지. PNG가 실제 투명인지 알파 확인(체커 무늬를 그린 것은 투명이 아님).
- 원본 크기·게임 크롭·대사창이 덮는 영역에서 각각 확인. 생성 성공만으로 완료 처리하지 않음.
- 파일명은 기존 자동 로더 경로 사용. 새 에셋은 등록 누락/플레이스홀더 확인.
- 지도 좌표, 사진 SVG, 조사 핫스폿은 이미지를 바꾸면 재확인. `?spots`는 조사 좌표 확인용.
- 7장 사진의 결손부는 공통 코드로 유지. 그림 생성 과정에서 ‘더 그럴듯한 모서리’로 별도 변형하지 않음.
- 기존 에셋 전체를 재생성하지 않는다. 결과물 용량을 확인하고 불필요한 대형 복제본을 `src/assets`에 남기지 않는다.

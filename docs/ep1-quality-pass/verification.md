# 구현 순서와 완료 판정

2026-10-24 · EP1-Q1

## 1. 실행 순서

1. **작업 트리 보존.** `git status --short`, 관련 diff 확인. 문서 작성 시점에는 EP1 시리즈 연결 장면 외에도 `.gitignore`, `assets.ts`, `audio.ts`, `music.ts`, `src/assets/music/` 변경이 있었다. 실제 현재 상태를 다시 확인하고 요청과 무관한 변경을 덮어쓰지 않는다.
2. **논리 기준 갱신.** `docs/ep1-rewrite.md`의 현재 개정 절에 EP1-R5와 시간 논증을 반영. 기존 개정 이력의 ‘10초 치명상’은 이전 설계임을 표시. 바이블의 1화 요약 중 같은 단정도 갱신. 시리즈 전체 진상은 유지.
3. **사건 자료와 후반부터 구현.** 새 보강 사실의 출처, 덧붙임, 자백 없는 무죄 논증, Q10 교체. 아직 이미지가 없어도 텍스트와 SVG로 확인 가능하게 만든다.
4. **초반 공개 순서와 대사.** 모두진술, 증언, nearMiss, 첫 폭행 뒤 Q07, 에필로그 압축.
5. **UI 최소 확장.** recap, 힌트 접근, 사진/카드의 실제 표시 크기. 새 상태와 CP·저장 동작을 함께 구현.
6. **필수 이미지 수정.** ART-01~03와 기존 art-guide 갱신. 정확한 증거 도식은 코드 유지.
7. **검증.** 타입/빌드 → 정상 새 게임 → 분기/저장 → 터치 → 공용 엔진 회귀. 선택 이미지 추가는 필수 검증 뒤 판단.

큰 작업 경계마다 타입 검사를 하되 변경 없이 같은 검사를 반복하지 않는다. 최종에는 빌드가 포함하는 타입 검사로 확인 가능하다. 사용자 플레이 전 자동 커밋하지 않는다.

## 4. 화면 검증표

스크린샷을 남길 지점: C01 지도 / C02 셔터 / Q07 상처 도식 / outside 두 녹음 / result 사진 선택·확대·Q10 / recap / 힌트 / 판결 / 사무실 엔딩.

- PC 1280×720와 1440×900, 터치 가로 844×390와 667×375.
- 터치 검수는 viewport 크기만 줄이지 말고 coarse pointer/touch 환경도 확인한다. `touchLayout()` 분기가 실행되는지 확인.
- 본문·선택지·시각의 실제 표시 크기 측정. 줄바꿈 후 텍스트와 확인 버튼 잘림 없음.
- 한 손가락으로 사진 후보 선택/취소/확인/힌트 가능. 키보드가 없어서 막히는 동작 없음.
- 사진 48초 온전한 모서리 / 58초 결손 / 증거 본체 그림 / 파편 도식이 일치.
- 골목은 닫힌 먼 문 또는 문이 없는 구도·검은 봉지. 녹음 장소를 오해시키지 않음.
- ‘관측’과 ‘주장’을 색 없이도 읽을 수 있음. 사진 설명문으로도 필요한 차이를 이해 가능.
- 문서 개정으로 새 이미지 경로가 생기면 총 용량·초기 로딩 변화 기록. 같은 대형 그림을 여러 이름으로 복제하지 않음.

## 5. 초회 플레이 평가

줄거리를 모르는 사람에게 설계 문서를 읽히지 않는다. 진행 중 해설이나 정답 도움을 먼저 주지 않는다. 이해 확인은 아래 네 지점에서 짧게 묻거나, 플레이 뒤 화면을 다시 보여 주며 확인한다.

| 지점 | 질문 | 기대하는 이해(정확한 이름/초 암기 불필요) |
|---|---|---|
| 첫 공방 뒤 | 무엇이 밝혀졌고 무엇은 아직 모르나요? | 카메라가 모두를 본 건 아니다. 범인은 아직 모름 |
| 첫 폭행 인정 뒤 | 이제 태오를 풀어 줄 수 있나요? | 첫 충돌은 태오가 아니지만 머리 상처는 별도 확인 필요 |
| Q10 직전 | 지금 무엇을 비교하고 있나요? | 상처 조각의 출처와 사진 속 상태, 태오가 나간 때 |
| 엔딩 뒤 | 자백이 없어도 태오를 구할 수 있었나요? 왜죠? | 방문 뒤에도 조각이 붙어 있었고 이후 행적도 확인돼 검찰 설명이 안 맞음 |

관찰할 것은 오답 횟수만이 아니다. ‘어느 자료를 왜 골랐는지’, ‘현재 질문을 잊었는지’, ‘정답을 맞혔는데 의미를 설명하지 못하는지’를 기록한다. 힌트를 쓴 것 자체는 실패가 아니다.

대사량 평가는 실제 읽기 기준으로 한다. 50~60분 같은 목표 시간을 맞추려고 문장을 늘리거나 줄이지 않는다. 첫 심문 전 체감 대기, 반복 설명에서 연타하는 구간, 감정 장면에서 멈추는 지점을 본다.

사람 초회 테스트를 확보하지 못했다면 구현 검증은 완료할 수 있지만 **‘초보자 이해도 검증까지 완료’라고 보고하지 않는다**. 실제 모바일 기기 대신 에뮬레이션만 사용했으면 그대로 명시한다.

완료 보고 형식: 변경 요약 / 변경 파일 / 논리와 이미지 수정 전후 / 실행한 검사와 결과 / 실제 플레이 확인 범위 / 미완료·선택 생략 사항 / 제작자가 직접 확인할 세 구간. 전면 재설계나 추가 승인 요청 대신 이 사양의 남은 구현 문제를 구체적으로 보고한다.

## 7. 이 문서 자체의 검토 기록

2026-10-24, 별도 개발자 관점 검토를 수행했다. 중요한 미정 결정은 없다는 결과를 받았으며, C02에서 정확한 02:45를 빼더라도 ‘02:00 이후’라는 범위는 필수 증언에 남겨야 한다는 지적을 반영했다. 이를 통해 선택적 흔들기를 읽지 않아도 셔터 반박의 전제가 성립하게 했다.

문서 내부 링크와 코드 블록 짝, diff 공백 오류를 검사했다. 이는 **설계 인계 검토**이며, 위 T01~T22나 실제 사용자 플레이를 실행했다는 뜻이 아니다.
